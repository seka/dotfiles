# PR の作成・更新と段階管理

## 作業に応じた手順

- PR を作成する場合は、以下の作成手順と「PR 作成前の確認」に従う。
- 既存 PR を更新する場合は、「既存 PR の更新」に従う。
- 複数 PR への分割を計画する場合や、stacked PR の先行更新・マージを後続へ反映する場合は、[段階計画と依存管理](references/pr-staging.md) を読む。単独 PR の作成・通常修正では、この詳細手順は不要。

## PR の作成

1. `git status` と `git branch --show-current` で作業ツリーと現在のブランチを確認し、`gh pr view` で既存 PR の有無を確認する
2. base branch を特定する（引数があれば使用、なければ関連 PR と依存関係を確認し、stacked PR の場合は親 PR のブランチ、それ以外はリポジトリの規約や既存 PR から開始ブランチを確認）
3. `git log [base]...HEAD --oneline` で全コミットを確認する
4. `git diff [base]...HEAD` で全変更を分析する
5. リポジトリの PR テンプレートを確認する（`.github/PULL_REQUEST_TEMPLATE.md`、`.github/PULL_REQUEST_TEMPLATE/`、ルートや `docs/` のテンプレートなど）。複数ある場合は変更に合うものを選び、指定された項目・構成を優先する。テンプレートがない場合は `gh` で同じリポジトリの直近・同種の PR 本文を確認し、見出し・項目順・記載の粒度を揃える。参考にできる既存 PR もない場合は、変更内容と確認結果が伝わる構成を変更規模に応じて決める
6. 下記の「PR 作成前の確認」を実施する
7. 最終差分と確認結果に合わせて PR を作成する:
   - タイトル: リポジトリの規約を優先し、指定がなければ70字以内、変更の要旨を英語で
   - 本文: 日本語で、リポジトリのテンプレートまたは既存 PR に合わせた構成を使い、実施したチェックの結果と未実施項目の理由を記載する

## PR 作成前の確認

- 通常作業でテスト・Lint・フォーマッターを実行しない運用でも、PR 作成前には変更に応じたローカルチェックを実行する。ドラフト PR も対象とする
- リポジトリの手順、CI 設定、実行スクリプトを確認し、変更に対応するテスト・Lint・整形チェック・ビルドを選ぶ。コードに影響しない文書のみの変更など、不要なチェックは理由を示して省略する
- フォーマッターは変更対象に絞って確認し、必要な整形を行う。無関係なファイルや既存の未コミット変更を巻き込まない
- 最終差分に対して既に成功したチェックは、対象や実行条件に変化がなければ結果を再利用する。整形・修正によって結果が無効になったチェックは再実行する
- 失敗は原因を確認して対応し、環境・権限などで実行できない場合は理由と残る確認事項を明示する。未実行や失敗を成功扱いしない。CI の結果を記載する場合も、対象 head と実際の状態を確認する
- 確認後に `git status` と `git diff` を見直す。整形などの未コミット差分は PR に含まれないため、残っている場合は扱いを明示する。commit・push は既存の許可とリポジトリ規約に従う

## 既存 PR の更新

- `gh pr view` で対象 PR の base/head と本文を確認し、最終差分と検証結果に合わせて更新する。既存 PR がある場合は重複して作成しない。
- コミット追加や push 後は、本文の変更内容・検証結果・制約・範囲外の項目を見直し、食い違う箇所を書き換える。開始ブランチの取り込みや競合解消だけで説明が変わらない場合は更新不要。
- push 前のチェックはリポジトリの規約に従い、確認方法と結果の扱いは「PR 作成前の確認」に準じる。
- 本文の更新には `gh pr edit --body-file "[本文ファイル]"` を使用する。

## 作成時のルール

- 依存する PR は親 PR のブランチを base にし、その段の変更だけが差分に含まれることを確認する。本文には親 PR のリンク、依存関係、マージ順を記載する。独立してマージできる変更は共通の開始ブランチから作る。
- 本文を一時ファイルに保存し、`gh pr create --base "[base]" --title "..." --body-file "[本文ファイル]"` を使用する。
- ドラフト PR の場合は `--draft` フラグを付与する。
